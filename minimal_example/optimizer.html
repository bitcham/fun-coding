1. 경사하강법 — 한 줄짜리 갱신

gradient $g = \partial\mathcal{L}/\partial\theta$는 "$\theta$를 키우면 손실이 늘어나는 방향"이다. 손실을 줄이려면 그 반대 방향으로 조금 가면 된다. 학습률 $\alpha$만큼:

$$ \theta \;\leftarrow\; \theta - \alpha\, g $$

모든 파라미터($E, W_1, \mathbf{b}_1, W_2, \mathbf{b}_2$)에 같은 규칙을 원소별로 적용한다.

# numpy (nlm.py)
def sgd_step(self, grads, lr):
    self.E  -= lr * grads["E"]
    self.W1 -= lr * grads["W1"]
    self.b1 -= lr * grads["b1"]
    self.W2 -= lr * grads["W2"]
    self.b2 -= lr * grads["b2"]
/* C (nlm.c) — 같은 규칙, 배열마다 원소별 */
void nlm_sgd_step(nlm_t *m, const nlm_grad_t *g, double lr) {
    for (int v = 0; v < VOCAB_SIZE; v++)
        for (int d = 0; d < EMB_DIM; d++) m->E[v][d] -= lr * g->E[v][d];
    /* W1, b1, W2, b2 도 동일하게 ... */
}
  • 모멘텀도, 적응 학습률도, weight decay도 없다 — 순수 경사하강법이다.
  • 작은 모델·작은 데이터에서는 이것으로 충분하다는 것을 이 데모가 보여준다.

2. full-batch GD vs mini-batch SGD

차이는 "한 번의 갱신에 몇 개의 학습 쌍을 보느냐" 하나뿐이다.

full-batch GDmini-batch SGD
gradient 계산학습 쌍 전체(24개)로무작위 부분집합(예: 8개)으로
한 epoch당 갱신 횟수1번여러 번 (24÷8 = 3번)
gradient 성격전체 손실의 정확한 기울기그 추정값 — 노이즈 있음
경로매끄럽게 내려감지그재그지만 자주 갱신
  • "S"(stochastic, 확률적)는 매 스텝 데이터를 무작위로 골라 gradient가 흔들린다는 뜻이다.
  • 그 노이즈가 손해처럼 보이지만, 큰 데이터에서는 오히려 이점이 된다:
    • 전체를 다 보기 전에 자주 갱신해 실측 시간(wall-clock)이 빠르다
    • 노이즈가 얕은 극소점을 빠져나오게 돕는다

이 데모의 학습 루프는 둘 다 지원한다 (nlm.py의 train):

for ep in range(epochs):
    if batch_size is None:                       # full-batch GD
        loss, grads = model.loss_and_grad(X, y)  # 24쌍 전부
        model.sgd_step(grads, lr)
    else:                                        # mini-batch SGD
        idx = rng.permutation(N)                 # 매 epoch 셔플
        for s in range(0, N, batch_size):
            bi = idx[s : s + batch_size]
            _, grads = model.loss_and_grad(X[bi], y[bi])  # 부분집합
            model.sgd_step(grads, lr)

두 방식의 수렴 곡선과 실측 시간 비교는 experiments/plot_gd_vs_sgd.py → results/gd_vs_sgd_curves.png, gd_vs_sgd_wallclock.png에 있다.

3. 학습률(learning rate) 고르기

  • $\alpha$는 한 스텝의 보폭이다.
  • 너무 작으면 굼뜨고, 너무 크면 골짜기를 건너뛰어 발산한다.

이 데모에서 학습률만 바꿔 2000 epoch 학습한 결과(실험 3, report.md):

lr최종 loss비고
0.010.69742000 epoch에도 미수렴 (너무 느림)
0.030.5026느림
0.10.4568양호
0.30.4503균형점 — 이후 실험 기본값
1.00.4486약간 더 낮음
3.00.4486큰 lr에서도 발산 안 함
왜 lr=3.0인데도 안 터지나? 보통 이렇게 큰 학습률은 발산한다. 여기서 괜찮은 건 모델이 작고 full-batch라 gradient가 노이즈 없이 매끈하고, 손실 표면이 단순하기 때문이다. 큰 모델·mini-batch에서는 이런 큰 학습률은 거의 항상 터진다.
  • 손실 하한. 최저 loss가 약 0.448에서 멈추는데, 이건 모델이 부족해서가 아니다.
  • 데이터 자체에 줄일 수 없는 모호성이 있다 — 예컨대 (<bos>) 다음에 철수는·영희는·짱구는 세 인물이 모두 가능하다.
  • 이 비축약 엔트로피(irreducible entropy)가 $\log(6)/4 \approx 0.448$의 바닥을 만든다 — 어떤 옵티마이저로도 그 아래로는 못 내려간다.

4. 왜 이 데모는 full-batch인가

  • 학습 쌍이 24개뿐이다 — 전부 한 번에 보는 비용이 무시할 만하니, 굳이 미니배치로 쪼갤 이유가 없다.
  • 그래서 C 버전(main.c)과 Python 기본 실행 모두 full-batch GD를 쓴다 — 매 epoch에 forward 한 번, backward 한 번, 갱신 한 번.
  • 실제 LLM 학습은 정반대다 — 데이터가 수십억 토큰이라 전체 gradient를 한 번 구하는 것조차 불가능하고, 그래서 mini-batch SGD가 필수다.
  • 이 데모의 full-batch는 "원리를 가장 깨끗하게 보여주는 최소 설정"이다.

5. 다음 단계 — Momentum·RMSProp·Adam

  • 순수 SGD의 두 가지 약점:
    • (1) 모든 파라미터·모든 축에 같은 학습률을 쓴다
    • (2) gradient 노이즈를 그대로 따라간다
  • 실무에서는 이를 보완한 옵티마이저를 쓴다.

이 데모 코드에는 들어있지 않지만, 큰 모델로 갈 때 만나게 될 흐름만 정리해 둔다:

옵티마이저핵심 아이디어
SGD (이 데모)$\theta \mathrel{-}= \alpha g$. 방향·크기 모두 gradient에 맡김
+ Momentum최근 gradient의 지수이동평균으로 방향을 매끄럽게 (관성)
RMSProp축별 gradient 크기로 나눠 스텝 크기를 정규화
AdamMomentum + RMSProp + 편향 보정. 현대 딥러닝의 기본값
  • 대규모 언어모델 학습에서는 거의 항상 AdamW + warmup + cosine 학습률 스케줄 조합을 쓴다.
  • 하지만 "왜 그 보완이 필요한가"는 순수 SGD를 먼저 손에 익혀야 보인다 — 그래서 이 최소 예제는 일부러 SGD에서 멈춘다.
